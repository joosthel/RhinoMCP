# ISO 13567 layers

ISO 13567 (Organization and naming of layers for CAD) defines layer names built from fields. It is heavier than AIA and is typically requested by public clients or in national implementations (for example Nordic countries and Germany-adjacent public works). Recalled from general knowledge: verify field lengths and code lists against ISO 13567-1/-2 and the client's national annex before delivering.

## Structure
Three mandatory fields, then optional ones, concatenated with fixed positions or separators depending on the national profile:

| Field | Meaning | Example |
|---|---|---|
| Agent responsible | Who owns/produces the data (discipline or party) | `A` architect, `S` structure |
| Element | What is represented (a code from a classification table) | `WALL`, `DOOR` |
| Presentation | How it is drawn | `OUTLINE`, `TEXT`, `HATCH`, `DIM` |
| Status (optional) | Project phase or state | new, existing, demolished |
| Scale (optional) | Intended drawing scale | `100` |
| Zone (optional) | Building part or area | `L1` |

## Practical use
- Ask the user which national profile and which classification table (Uniclass, DIN 276, CI/SfB variants) applies. Do not invent codes.
- Delimiter is profile specific; use a custom scheme JSON (see scheme-format.md) with `delimiter` set to the profile's separator.
- Keep a mapping sheet (old layer to new layer, object counts) for the user to approve before `layers_apply_scheme`.
- Presentation fields suit the Make2D output split: visible, hidden, section, hatch, annotation.
